# Pixel Reframe Lab

画像の細かい一部分を矩形で選び、近くの画素をコピー、反転、ぼかし、モザイク、透明化できます。帯の伸縮、反復、削除、余白生成、回転、反転、切り抜きも、すべてブラウザ内で処理します。

公開先

https://abcderp2.github.io/roof-stretch-editor/

## 最初の使い方

1. 「サンプル画像で試す」または「画像を選ぶ」を押します。
2. 左の「元画像」で、直したい場所を指またはマウスで囲みます。
3. 左側の「修正方法」を選びます。
4. 右の「結果」で仮の仕上がりを確認します。
5. 「部分修正を追加」を押します。
6. 必要なら別の場所を囲み、修正を重ねます。
7. 「保存と設定レシピ」を開き、画像を保存します。

失敗した場合は「元に戻す」を押してください。最大40段階まで設定を戻せます。

## 細かい一部分の修正

部分修正は最大20個まで重ねられます。

- 近くの画素をコピー
- 左右反転
- 上下反転
- ぼかし
- モザイク
- 1列引き伸ばし
- 単色で覆う
- 透明にする

「近くの画素をコピー」では、黄色の枠が修正先、水色の枠がコピー元です。コピー元を左右上下へ動かし、模様や明るさが近い場所を選びます。

追加済みの修正は一覧から選び直せます。範囲、方法、強さを変更して更新できます。

## 元画像と結果のプレビュー

元画像と結果を常に同時表示します。

- 左側で修正範囲を選びます。
- 右側へ修正前の仮結果が自動反映されます。
- 50%から400%まで拡大できます。
- 選択範囲は0.1%単位の数値でも調整できます。
- 拡大後は各プレビュー枠をスクロールして細部を確認できます。
- スマートフォンでは上下表示、広い画面では左右表示になります。

プレビュー解像度は端末性能に合わせて自動調整されます。保存画像の解像度とは別です。

## 帯の変形

横帯または縦帯を選び、伸ばす、縮める、繰り返す、鏡面反復、1列引き伸ばし、削除、循環移動を行えます。

空、壁、床、布、模様など、急な変化が少ない範囲で使うと境界が目立ちにくくなります。

## 余白と画像全体の調整

上、右、下、左へ別々の余白を追加できます。余白は鏡面、反復、端の引き伸ばし、単色、透明から選べます。

回転、左右反転、上下反転、4辺からの切り抜きにも対応します。

## 設定レシピ

設定レシピはJSONファイルです。画像そのものは含みません。部分修正の位置と方法、帯の変形、余白、回転、反転、切り抜き、保存設定を保存します。

同じ大きさや似た構図の画像へ設定を再利用できます。レシピは最大96KB、部分修正は最大20個に制限しています。

## 対応画像と上限

JPEG、PNG、WebPに対応します。HEIC、AVIF、GIF、SVGは読み込み対象外です。

入力上限は18MB、2000万画素、縦横10000pxです。保存上限は端末性能に応じて1000万から2400万画素です。最大の縦横を1280pxまたは2048pxへ下げると、メモリの少ない端末でも保存しやすくなります。

## プライバシーとセキュリティ

- 画像はサーバーへ送信しません。
- 外部API、広告、解析、外部JavaScript、外部CSS、外部フォントを使用しません。
- JPEG、PNG、WebPの実データ署名と寸法を復号前に検査します。
- ファイル表示形式と実データが一致しない場合は拒否します。
- Content Security Policyで外部通信、埋め込み、フォーム送信を拒否します。
- 画像データをLocalStorageへ保存しません。
- レシピのサイズ、形式、項目数、数値範囲を検証します。
- ファイル名は保存前に安全な文字へ整形します。

GitHub PagesではHTTPレスポンスヘッダーをすべて自由に設定できないため、HTML内のContent Security Policy、外部依存の排除、入力検証、安全なDOM操作を中心に防御しています。

特定企業の非公開な社内基準への適合や認証を示すものではありません。公開Webアプリで一般的な最小権限、依存最小化、入力検証、自動テスト、変更レビュー、戻しやすいマージを採用しています。

## 低性能端末への配慮

- 端末のメモリ、CPUコア数、画面幅からプレビュー上限を調整します。
- 保存時は指定最大寸法へ縮小してから安全上限を判定します。
- 処理途中のCanvasは使用後に縮小し、メモリ解放を促します。
- 部分修正数、履歴数、画像容量、画素数に上限があります。
- 外部ライブラリ、ビルド処理、Web Worker、WebAssemblyは必須ではありません。

## ファイル構成

```text
roof-stretch-editor/
├── index.html
├── style.css
├── responsive.css
├── core.js
├── patch-render.js
├── render.js
├── app-base.js
├── app-patches.js
├── app-io.js
├── app.js
├── README.md
├── SECURITY.md
├── CONTRIBUTING.md
├── LICENSE
├── .nojekyll
├── tests/
│   ├── core.test.js
│   ├── render.test.js
│   ├── static.test.js
│   └── app-smoke.test.js
└── .github/workflows/quality.yml
```

core.jsは設定と検査、patch-render.jsは矩形修正、render.jsは全体描画、app-base.jsは状態、app-patches.jsは部分修正UI、app-io.jsは入出力、app.jsはプレビューとイベントを担当します。

無料プランの一般的なAIでも、修正対象を1ファイルへ絞りやすい構成です。

## 開発と検査

Node.jsの追加パッケージは不要です。

```text
node --check core.js
node --check patch-render.js
node --check render.js
node --check app-base.js
node --check app-patches.js
node --check app-io.js
node --check app.js
node tests/core.test.js
node tests/render.test.js
node tests/static.test.js
node tests/app-smoke.test.js
```

GitHub Actionsでも同じ検査を実行します。

手動確認では、サンプル生成、2画面表示、矩形選択、8種類の部分修正、追加と更新と削除、履歴、400%拡大、スマートフォン表示、3形式保存、外部通信なしを確認します。

## 変更を戻す方法

機能追加は作業ブランチとPull Requestで行い、squash mergeします。問題が見つかった場合は該当Pull RequestをRevertすると、変更全体を1回で戻せます。
