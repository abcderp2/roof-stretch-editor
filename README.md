# Roof Stretch Editor

画像の屋根部分を縦方向に伸ばす、依存ライブラリなしの軽量なブラウザ画像編集ツールです。

公開先

https://abcderp2.github.io/roof-stretch-editor/

## 特徴

- GitHub Pagesで無料公開できます。
- HTML、CSS、JavaScriptだけで動作します。
- Node.js、ビルド処理、外部APIは不要です。
- 画像は外部へ送信せず、ブラウザ内だけで処理します。
- スマートフォン、タブレット、ノートPC、デスクトップPCに対応します。
- JPEG、PNG、WebPの読み込みと保存に対応します。
- 低スペック端末で停止しにくいよう、画像容量と画素数に上限を設けています。

## 使い方

1. 「画像を選ぶ」から屋根が写っている画像を選びます。
2. 「範囲の上端」と「範囲の下端」で、伸ばしたい屋根部分を指定します。
3. 「伸ばす量」を調整します。
4. 「仕上がりを確認」で結果を確認します。
5. 保存形式を選び、「画像を保存」を押します。

境界が目立つ場合は、模様や色が急に変化しない位置を上端と下端に選んでください。

## 対応環境

JavaScriptとCanvasが利用できる、現在サポートされている一般的なブラウザを対象とします。

- Google Chrome
- Microsoft Edge
- Mozilla Firefox
- Apple Safari
- Android版Chrome
- iPhone、iPad版Safari

古いブラウザやアプリ内ブラウザでは、画像保存が正常に動作しない場合があります。その場合は通常のブラウザで開いてください。

## 画像の上限

端末のメモリ不足やブラウザ停止を避けるため、次の上限を設けています。

- ファイル容量は12MBまで
- 元画像は1600万画素まで
- 元画像の縦横は8192pxまで
- 保存画像は2000万画素まで
- 保存画像の縦横は8192pxまで

上限を超える場合は、端末の写真アプリなどで画像を縮小してから読み込んでください。

## パソコンで動作確認する方法

特別な開発環境は不要です。

1. リポジトリの「Code」を押します。
2. 「Download ZIP」を選びます。
3. ZIPを展開します。
4. `index.html`をブラウザで開きます。

ブラウザの制限でローカル表示が正常に動かない場合は、GitHub Pagesへ公開して確認してください。

## GitHubへ更新をアップロードする方法

初心者が変更を戻しやすいよう、1回の更新で変更する目的を1つに絞ります。

1. GitHubでこのリポジトリを開きます。
2. 変更するファイルを開き、鉛筆のボタンを押します。
3. 内容を変更します。
4. 画面下部のコミットメッセージに、変更内容を短く書きます。
5. 可能な場合は新しいブランチを作成し、プルリクエストを作ります。
6. 「Files changed」で意図しない変更がないか確認します。
7. 問題がなければマージします。

直接mainブランチを変更するより、作業用ブランチとプルリクエストを使う方が元に戻しやすくなります。

## GitHub Pagesで公開する方法

1. リポジトリ上部の「Settings」を開きます。
2. 左側の「Pages」を開きます。
3. 「Build and deployment」のSourceで「Deploy from a branch」を選びます。
4. Branchで`main`と`/(root)`を選びます。
5. 「Save」を押します。
6. 公開処理の完了後、次のURLを開きます。

```text
https://abcderp2.github.io/roof-stretch-editor/
```

初回公開や更新の反映には少し時間がかかる場合があります。

## よくある問題

### 画像を選べない

JPEG、PNG、WebP形式か確認してください。HEIC形式の写真は、端末の写真アプリなどでJPEGへ変換してから使用してください。

### 画像が大きすぎると表示される

端末の写真アプリで画像を縮小してください。大きな画像を無制限に処理すると、低スペック端末でブラウザが停止する可能性があります。

### 保存ボタンを押しても見つからない

ブラウザのダウンロード一覧や、端末の「ファイル」アプリを確認してください。アプリ内ブラウザを使用している場合は、通常のSafari、Chrome、Edge、Firefoxで開き直してください。

### 境界線が目立つ

伸ばす範囲の上端と下端を、色や模様が近い場所へ移動してください。このツールは選択した帯を縦方向に拡大するため、急に模様が変わる場所では境界が見えやすくなります。

### GitHub Pagesが404になる

SettingsのPagesで、公開元が`main`と`/(root)`になっているか確認してください。ファイル名が`index.html`の小文字になっていることも確認してください。

## セキュリティとプライバシー

- 外部API、外部JavaScript、外部CSS、外部フォントを使用しません。
- 画像データをネットワークへ送信しません。
- 入力ファイルの種類、容量、画像サイズを検証します。
- ユーザーが選んだファイル名はHTMLとして挿入しません。
- `eval`や動的スクリプト生成を使用しません。
- Content Security Policyで不要な通信や埋め込みを制限します。
- 不要なカメラ、位置情報、通知などの権限を要求しません。

GitHub Pagesでは、リポジトリ側からすべてのHTTPセキュリティヘッダーを自由に設定できません。そのため、このプロジェクトではHTML内のContent Security Policy、外部依存を持たない構成、安全なDOM操作を中心に対策しています。

画像を処理する際は、ブラウザが画像を端末メモリへ展開します。個人情報が含まれる画像を共有端末で扱う場合は、作業後にブラウザのダウンロード履歴や保存先も確認してください。

## 保守方針

このプロジェクトは、初心者が無料で長期間保守できることを品質基準とします。

- GitHub Pagesだけで公開できる状態を維持します。
- 追加課金が必要なサービスやAPIを導入しません。
- HTML、CSS、JavaScriptを基本とし、依存関係を増やしません。
- Node.jsやビルド環境を必須にしません。
- 機能追加は小さな差分に分けます。
- 入力検証、例外処理、分かりやすい日本語エラーを維持します。
- エントリークラスのスマートフォンやタブレットを想定します。
- Chrome、Edge、Firefox、Safariの一般的な機能だけを使用します。
- 外部通信を追加する変更は、必要性とプライバシーへの影響を先に確認します。
- READMEに不足や誤りが見つかった場合は、コードと同じ変更内で修正します。
- 採用した技術やディレクトリ構成は、明確な利点がない限り変更しません。
- 変更が必要な場合は、既存資産を活用し、破壊的変更を避け、最小限の差分で移行します。

特定企業の内部基準への適合や認証を示すものではありません。一般的な品質管理、セキュアな初期設定、最小権限、入力検証、変更レビュー、段階的改善の考え方を、無料で維持できる範囲に落とし込んでいます。

## 変更前の確認項目

コードを変更したら、次を確認します。

1. 画像を選択できること
2. 範囲スライダーが逆転しないこと
3. 仕上がりプレビューが更新されること
4. PNG、JPEG、WebPを保存できること
5. 大きすぎる画像で分かりやすいエラーが出ること
6. 画像を外して別の画像を選び直せること
7. スマートフォン幅で横にはみ出さないこと
8. キーボードだけで主要操作ができること
9. ブラウザの開発者ツールに予期しないエラーがないこと
10. 外部ネットワーク通信が発生していないこと
